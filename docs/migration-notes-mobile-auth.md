# Mobile SDK & Server Update Migration Notes

## Summary of Changes
Fixed a Google Sign-In issue where the server was rejecting ID tokens from the mobile app due to a Client ID mismatch.

## Server Updates
- Updated `NEXT_PUBLIC_GOOGLE_CLIENT_ID` in `.env.local` to match the mobile app's Client ID (`458694282265-dnveen6f8uqgaek8ka22q1t7v5jdi223.apps.googleusercontent.com`).
- This ensures the server correctly validates ID tokens generated by the mobile application.

## Mobile SDK Update (v1.0.30)
The mobile SDK has been updated to improve Google Sign-In handling.

### Required Actions for Mobile Team
1. **Update SDK Version**: Ensure the mobile app is using `@hakgyo/expo-sdk` version `1.0.30` or higher.
2. **Configuration Check**: Verify that your `app.json` or `app.config.ts` uses the correct Google Services configuration that corresponds to the Client ID `458694282265-dnveen6f8uqgaek8ka22q1t7v5jdi223.apps.googleusercontent.com`.
3. **Testing**: 
   - Perform a fresh install of the app.
   - Test Google Sign-In.
   - Verify that the "Invalid id token" error is resolved.

### Troubleshooting
If you still encounter "Invalid id token" errors:
- Double-check that the `google-services.json` (Android) or `GoogleService-Info.plist` (iOS) files are up to date and match the Firebase/Google Cloud Console project for the updated Client ID.
- Ensure no cached tokens are being used (clear app data/storage).
